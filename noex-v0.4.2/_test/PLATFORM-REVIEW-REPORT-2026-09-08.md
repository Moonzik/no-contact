## 一、真机渲染效果

### 1.1 我修掉的（会真机出问题的）

#### 🔴 P0 · 主包 1.8 MB，逼近 2 MB 硬限制 → 现在 171 KB

这是**唯一一个会让你连上传都失败**的问题。

```
images/agent.png     1024x954  681 KB  →  480x447  9.6 KB
images/appicon.png   1024x954  681 KB  →  480x447  9.6 KB
────────────────────────────────────────────────────
主包 1.8 MB  →  171 KB   （省 1.31 MB）
```

- 这两个图在 UI 里最大只显示到 `220rpx`（≈330px @3x），1024px 纯属浪费
- 压缩前：代码 194 KB + 图片 1362 KB。微信主包上限 **2048 KB**，余量只剩 0.5 MB，稍加功能就会爆
- 压缩后：余量 1.87 MB，随便迭代
- **质量验证**：PSNR **44.0 dB**（阈值 35 dB 即肉眼无损），且原图无透明通道，PNG-8 量化无损
- 原图已备份在 `images/_orig_backup/`，不满意可随时还原

> 顺带说明：`_orig_backup/` 要加进 `packOptions.ignore`，否则备份会重新把包撑大。**这条我还没做，见第五节待办。**

#### 🟠 关于页版本硬编码 "v0.3.0 原型"

实际已 0.4.2。已改为从 `app.globalData.version` 动态读取。

顺手删了两句**审核会扣分**的话：
- "原型" → 审核员会认为功能不完整
- "正式版将接入大模型" → 主动暴露未实现功能，且大模型服务需额外资质

## 二、iOS / 安卓差异

### 2.1 已修（4 项）

| # | 问题 | 影响 | 修法 |
|---|---|---|---|
| 1 | **`new Date(str)` 日期解析** | iOS 老 JSCore 对 ISO 字符串可能按 UTC 解析，东八区偏 8 小时 → **跨天时戒断天数差 1 天** | 新增 `util.parseDate()` 数字构造 + `dayNum` 改用 `Math.round` |
| 2 | **居中文本字距偏移**（5 处） | CSS 规范里 `letter-spacing` 会在**末字符后也加间距**，导致居中文本视觉偏左 N/2。安卓更明显 | 加 `text-indent: 同值` 抵消 |
| 3 | **`backdrop-filter` 缺前缀** | iOS 需 `-webkit-` 前缀；安卓旧 WebView 完全不支持 → 蒙层透明 | 补前缀（背景兜底原本就有） |
| 4 | **称谓不统一**（28 处） | 回复文案里混用小写 `ta` 与 `TA`，你之前明确要求统一 | 批量改为 `TA`，**关键词池（匹配用户输入的「想找ta」等）完好保留** |

**第 1 项的证据**（说明这不是我臆想的风险）：

```
环境 UTC+8
new Date("2026-09-08")        → 08:00:00   ← 按 UTC 解析，偏移 8 小时
new Date("2026-09-08T00:00:00") → 00:00:00   ← 原写法，现代引擎正确
parseDate("2026-09-08")       → 00:00:00   ← 新写法，任何引擎都正确
```

原写法 `startDate + 'T00:00:00'` 在现代 iOS 上**大概率正常**，但老 JSCore 有历史坑。改成数字构造是彻底消除风险，属**防御性修复**，不是修必现 bug——这点我要说清楚。

新增 19 条测试锁死：跨月 / 跨年 / 闰年 / 时区 / 非法输入 / 未来日期。

### 2.2 已知残留风险（4 项，未改）

| 风险 | 说明 | 建议 |
|---|---|---|
| **衬线字体降级** | `--serif` 首选 `Noto Serif SC`，安卓几乎没有 → fallback 到黑体，标题设计感会掉 | 真机确认；若不满意可内置字体子集（会增大包体） |
| **`grayscale` 滤镜** | 影子头像靠它做"褪色"效果，低版本安卓 WebView 支持不全 → 显示彩色 | 真机确认；备选方案是预置一张灰度图 |

## 三、微信审核视角

### 3.1 已修（会直接拒审的）

#### 🔴 P0 · 隐私接口未声明 → 真机上功能直接调用失败

```
wx.chooseMessageFile  @yingzi.js:133   （导入聊天记录）
wx.setClipboardData   @me.js:76        （导出数据）
```

微信 2023-09-15 起强制：使用隐私接口必须在 mp 后台配置《用户隐私保护指引》+ 代码开 `__usePrivacyCheck__`。**两者缺一，真机上这两个功能会直接 fail。**

已做：
- `app.json` 加 `"__usePrivacyCheck__": true`
- 关于页加《用户隐私保护指引》入口（`wx.openPrivacyContract()`），满足「协议可触达」
- 新增 `PRIVACY.md`：mp 后台勾选清单 + 用途文案 + 完整协议正文

#### 🟡 红线词扫描：干净

扫了医疗承诺 / 绝对化 / 诱导分享 / 虚拟支付 / 涉政 5 类，**0 命中**。

唯一命中的「治疗」是 `me.wxml` 的**免责声明**"本产品不替代专业心理治疗"——**这是审核加分项，保留**。（我一开始的规则误报了，已修正为识别否定语境。）

### 3.2 需要你去 mp 后台操作（5 步）

| # | 事项 | 位置 | 说明 |
|---|---|---|---|
| **1** | **配置《用户隐私保护指引》** | 设置 → 服务内容声明 | ⚠️ **必须先于代码提审**，否则审核员测隐私接口时报错直接拒。勾选「剪贴板」「用户选择的文件」两项，**其余一律不勾** |
| 2 | 设最低基础库 ≥ 2.25.0 | 设置 → 版本 | `enhanced` scroll-view 需要 |
| 3 | 类目选「工具 → 效率」 | 设置 → 基本设置 | 别选游戏（无积分/养成/排行），避开心理/医疗（要资质） |
| 4 | 填简介 | 设置 → 基本设置 | 之前给过 ≤120 字版本 |
| 5 | 上传小程序图标 | 提审时手动选 | 用 `images/appicon.png`（原图在 `_orig_backup/`） |

**第 1 步的完整操作清单和可直接复制的文案在 `PRIVACY.md`。**

### 3.3 最可能被质询的点 + 应对话术

#### ⚠️ 头号风险：影子功能导入他人聊天记录

审核员可能认为「收集用户通讯内容 / 侵犯他人隐私」。**建议提审时在补充说明里主动写**（主动说明比被问再解释通过率高得多）：

> 影子功能的聊天记录导入，由用户在自己的微信会话中**主动选择文件、逐次授权**，
> 文件在**本机内存中解析**，仅提取说话特征（平均句长、高频语气词、反问率），
> **不上传服务器、不留存原始文本、不读取用户未选择的内容、不涉及他人账号**。

#### ⚠️ 次风险：心理危机相关内容

代码里有自杀/自危机词检测与心理热线。审核可能误判为医疗健康类。

应对：
- `me.wxml` 已有免责声明"本产品不替代专业心理治疗"——**保留，这是护身符**
- 类目别选「医疗」「心理」
- 若被要求说明：这些是**安全兜底机制**，用于识别用户危机倾向并引导至专业援助，不提供任何诊断或治疗

#### ✅ 有利因素

- 纯本地存储，无服务器、无用户系统、无 UGC 传播 → 内容安全压力小
- 无虚拟支付、无诱导分享、无社交关系链 → 避开了大部分红线
- 主包 171 KB → 远低于限制，加载体验好
