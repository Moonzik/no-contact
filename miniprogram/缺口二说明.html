缺口二说明

体验与留存六项：文字日记 · 备份还原 · 换断联对象 · 打卡提醒 · 留白瓶仪式 · 流量主广告位
NOEX v0.9.13（build gaps2-v9.13） · 2026-09-11 · 全量 12 套件 1136 项测试全绿
一句话：六项里四项已经完全可用（日记、备份还原、换段、留白瓶仪式），两项需要你去做一次后台操作才会亮起来（打卡提醒要申请订阅消息模板、广告位要开通流量主）。 没有后台配置的那两项，代码里做成了「不存在」而不是「假装能用」——点进去会如实告诉你还差什么，不会给你一个假的成功提示。

1 · 文字日记（今天页）已可用

打卡卡片下面多了一张「写给自己」。每天写一句就够，最多 200 字。

  • 写完可以随时改——同一天再写是覆盖，不会堆出两条
  • 往期能回看：卡片底部「往期 N 天」展开，倒序列出写过的话
  • 日历上有点：写过日记的日子，格子里会有一个小小的圆点，点一下就能看到那天写了什么
  • 删掉今天这个入口放在角落，不显眼但要找得到

设计上的克制：日记卡片没有天数徽章、没有进度条——它不是打卡任务，是给自己留的痕迹。
写日记需要先登录一次（和打卡、留白瓶同一个口径），你说的话仍然只在你手机里。

2 · 备份还原（我 → 数据）已可用

原来只能导出，现在能导回来了。换手机、重装小程序都不再等于数据清零。

怎么用：我 → 导入备份 → 「从剪贴板导入」（把之前导出的那段 JSON 复制好）或「从聊天选文件」（备份存成了 .json / .txt）。

刻意做成两步，不让人一键把数据冲掉

  • 第一步只核对、不写库：先告诉你这份备份里有什么（开始日、打卡次数、对话条数、留白瓶、日记天数、过往段数、是否含登录信息），确认无误再点「确认导入」
  • 第二步才覆盖，并且覆盖前自动给当前数据存一份快照
  • 事后后悔：数据卡片里会多出「撤销上次导入」这一行，一键回到导入前

认不出来的东西一律拒绝并说明原因（空剪贴板 / JSON 解析失败 / 结构不对 / 不是本小程序的备份），不会硬塞进去把现有数据弄脏。
导入的是老版本备份也没关系：缺的新字段（日记、过往段、提醒状态）会在导入时自动补齐。

3 · 换断联对象（我 → 开始新的一段）已可用

以前只有「断联开始日」和「TA 的代号」两个字段，复发重启后没法干净地开新的一段。现在有明确的出口了。

点「开始新的一段」之后怎么处理
打卡天数 / 打卡次数 / 断联日历从今天从零开始
TA 的代号清空
影子（模仿对象）清空——他认的是具体的人，不换会认错人，得重新导入聊天记录
日记 / 留白瓶 / 和小白的对话全部保留——那些是你自己的东西，不属于某一个人
现在这一段归档进「过往记录」，随时能回看（代号、起止日期、共几天、撑住几次、断过几次）

过往记录最多留 20 段，只存摘要和日期，不存对话内容——避免占用手机存储。

4 · 打卡提醒要你先申请模板

先说清楚一件事：小程序没有任何「本地定时通知」能力，微信不让小程序自己弹提醒。能把你叫回来打卡的官方通道只有一条——订阅消息：用户授权 → 云端按模板发一条。

代码里的客户端部分已经写好了（授权、记录订阅状态），但缺一个模板 ID，这个只能你去后台申请。

你要做的

  1. mp 后台 → 功能 → 订阅消息 → 选用模板（工具类目能选的模板有限，如果没有合适的，这项就先放着）
  2. 拿到模板 ID，填进 utils/config.js 的 REMINDER_TMPL_ID

提醒的门槛记一下：订阅消息是一次授权一条，发完要再授权。真要每天推，通常得让用户多点几次订阅，或者用云函数定时任务配合。
在配好之前，点「每日提醒」会弹一段说明，并给一个土办法：把小程序添加到「我的小程序」，每天顺手往下拉。

5 · 留白瓶仪式（封存 / 销毁）已可用

留白瓶原来只能存和看，缺一个「结束」的动作。现在有三种。

  • 封存：写完勾上「封存起来」，或长按旧的一条选封存。封上之后正文在列表里不显示，只留一句「封存中 · 2027 年 9 月 11 日打开」——这是自己给自己设的门，不是加密，但看不见就是看不见
  • 提前打开：封存中的条目长按可以提前开，会先问一句「提前打开就失去封存的意义了，确定吗？」
  • 销毁：长按选销毁，二次确认后从瓶子里删掉

操作入口刻意做成长按而不是常驻按钮——销毁这种事越不容易误触越好。列表上方会显示「瓶子里 N 句 · 封着 M 句」。

6 · 流量主广告位要你先开通流量主

广告位的代码位已经预留在今天页和留白瓶页底部，但 utils/config.js 里的 AD_UNIT_ID 是空的——空着的时候整块不存在，不占位、不留白、不报错。

开通路径：小程序上线后 → mp 后台 → 推广 → 流量主（个人主体也能开，门槛是累计独立访客 UV，以后台提示为准）→ 「广告位管理」新建一个 Banner 广告位 → 把 adunit- 开头的 ID 填进 utils/config.js。

提醒一句：这款产品的用户大多处在情绪低谷，广告出现太多会伤留存。建议先用最克制的位置（页面最底部、不遮挡任何功能），别加激励视频和插屏。
另外，iOS 端小程序内不允许购买虚拟商品，但看广告不受影响。

你要做的只有两件事（可做可不做）

1. 申请订阅消息模板 → 填进 utils/config.js 的 REMINDER_TMPL_ID，打卡提醒就活了。（工具类目没有合适模板就先放着，不影响其它功能）

2. 上线后开通流量主 → 把广告位 ID 填进 AD_UNIT_ID，广告位自动出现。

其余四项（日记、备份还原、换段、留白瓶仪式）现在就能用，开发者工具点「编译」即可。云函数不用动，这次改的全是小程序端。
